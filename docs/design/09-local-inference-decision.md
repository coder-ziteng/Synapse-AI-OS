## 0. 文档目的

[需求目标 Phase 6](../需求目标.md) 登记的决策点——「本地推理运行时：决策 Rust 推理栈（candle/burn 裁剪版）vs 用户态 libc shim + llama.cpp」——以及 [避坑指南 §5](../需求目标.md) 预留的三选一，收敛前 **P6.8-T2 无法启动**。本文档回答四个问题：

1. 为什么「直接跑 llama.cpp」在本项目不成立（约束是什么）？
2. 三个候选各自的真实工作量、风险与架构一致性如何？
3. 首期推荐哪条路径、保留什么埋点？
4. 什么触发条件下重新决策（何时才值得上本地推理）？

## 1. 问题约束

| # | 约束 | 出处 | 对推理的影响 |
|---|------|------|-------------|
| C1 | 用户态是裸机 no_std ABI：syscall 为微内核自有接口（cap 模型），无 libc/POSIX 语义层、无动态链接 | [Doc 02](02-userspace-abi-and-process-model.md) | llama.cpp（C++/POSIX 依赖：线程、mmap、异常、RTTI、文件系统）**跑不起来**——避坑指南 §5 的前置判断成立 |
| C2 | 内核堆仅 1MB 池；物理页分配器 `MAX_FRAMES=128MB` 位图上限、恒等映射仅 0-4GiB | [heap.rs](../../kernel/src/heap.rs)、R16/GAP-4 | 1B 参数 Q4 量化模型 ≈ 0.7GB 权重 + KV cache，**当前内存子系统装不下任何有意义的本地 LLM**；P6.0-T1（E820 真实探测）已于 2026-09-27 完成，但 buddy 升级与高端映射（P6.0-T2/T3）未启动 |
| C3 | 无持久化存储栈（virtio-blk 属 Phase 6 远期） | R6 | 模型文件无处放置：initramfs 塞 GB 级权重不现实，加载路径不存在 |
| C4 | 唯一网络出口不变量：所有出网必须经外交工具（Device/MMIO/IRQ 网络能力唯一持有者） | [Doc 04 §3](04-diplomat-channel-architecture.md) | 远程 API 调用天然走外交工具主路径，**不需要**本地推理参与；反之本地推理与网络栈解耦，属纯用户态算力问题 |
| C5 | 「AI 原生」首期定义已收敛为：外交工具 = 远程 AI API 代理 | 需求目标 §三 Phase 5、[Doc 04 §5.4](04-diplomat-channel-architecture.md)（"Agent 调用远程 AI API（首期外交工具的'AI 原生'主路径）"） | 远程代理路径**已有设计文档背书**，本地推理是其补集（脱机场景） |
| C6 | 原始构想中外交工具定位：受控通道/海关（协议适配、安全规范、审计），**不含模型推理** | [原始思路.md](../../原始思路.md)（"外交工具不是 Agent 本身……所有跨 OS 请求必须通过外交工具这个海关"） | 把推理栈塞进外交工具会稀释其"海关"定位；本地推理若存在，应挂在 Agent 运行时/独立推理服务侧 |

**动机澄清**：本地推理的唯一刚需是**脱机能力**——外网不可达（无 AP、防火墙、安全演练、跨 OS 对抗断网）时 OS 仍保有最低限度 AI。其余场景（S4 embedding、Agent 对话）远程 API 均能覆盖。决策的本质是：**为这个"唯一刚需"付多大代价、现在付还是以后付**。

## 2. 三候选对比

### 候选 A：candle/burn no_std 裁剪版（Rust 原生推理栈）

- **内容**：引入 candle-core（no_std 特性）或 burn 推理子集，在用户态独立推理服务实现 matmul 内核；加载量化小模型（≤1B），暴露与远程 API 同构的推理接口供 Agent/外交工具路由。
- **可行性**：crate 方提供 no_std/精简构建路径，但属实验特性——GEMM 后端、模型算子覆盖、SSE/AVX 手工调优都需自行验证；技术栈与内核同质（纯 Rust），ABI 上无硬阻塞。
- **致命时序问题**：即便代码打通，**C2（内存）与 C3（存储）未解**——buddy 分配器 + 高端映射 + 存储栈就位之前，模型进不了内存。本地推理实际上被 P6.0-T2/T3 与 Phase 6 存储栈**双重排期依赖**，而这三项都未排定完成时间。
- **工作量**：P6.8-T2 原估 1-3 窗口明显偏乐观；含算子验证、模型裁剪、性能调优，实为**独立子系统量级（3~6+ 窗口）**。
- **优点**：Rust 原生、无 POSIX 包袱；能力模型天然契合；长期自主可控。
- **缺点**：工作量大头在无收益期（脱机场景尚未成为产品阻塞）；1B 级模型实际能力有限；受 C2/C3 排期硬约束。

### 候选 B：极简 libc shim + llama.cpp

- **内容**：为用户态实现 llama.cpp 所需 libc 子集（malloc/mmap/线程/stdio/math）+ C++ 运行时（异常/RTTI），移植 llama.cpp 及 GGUF 生态。
- **可行性**：llama.cpp 对 POSIX 面依赖宽（std::thread、exception、filesystem、mmap）；shim 工作量 ≈ **重写一个 mini Linux 用户态**；且 libc 语义（信号、fork、路径）与 cap 模型存在结构性错配——兼容层会制造绕过 cap 校验的暗道（违背 Doc 01/02 安全模型）。
- **工作量**：**6+ 窗口起步**，失败模式（C++ 工具链在 nightly 裸机上碎裂）难诊断。
- **优点**：唯一直接吃到 GGUF 模型生态的路径。
- **缺点**：避坑指南 §5 已明确警示"工作量巨大"；与维护 C++ 子项目绑定的长期负担；与本项目的工程哲学（拒绝重复造轮子、unsafe 收紧）正面冲突。

### 候选 C：承认外交工具仅远程 AI API 代理（避坑指南 §5 推荐）

- **内容**：P6.8-T2 收敛为"不部署本地推理"并**文档化收口**：
  1. 外交工具增加推理后端配置项（provider 路由：远程 API 为唯一实装后端）；
  2. 定义**脱机降级策略**：网络不可达 → fail fast + 审计事件 + 向发起 Agent 返回结构化错误（`InferenceUnavailable`），Agent 依 L4 策略挂起或走本地缓存兜底；
  3. **埋点保留**：定义 `InferenceProvider` trait（remote 实装 + local 占位），未来选 A 仅增实现、不动上层。
- **优点**：风险最低（避坑指南 §5 原话"风险最低且符合'外交工具'原始定义"）；零新子系统；与 C4/C5/C6 全一致；P6.8-T2 缩为 1 窗口内任务；"AI 原生"叙事闭环不变（Agent → IPC → 外交工具 → HTTPS → 远端 LLM）。
- **缺点**：完全脱机场景无 AI 能力（首期**承认该限制**并登记为已知边界）；对外部 API 的网络/凭据/隐私依赖由 Security Gateway 脱敏与审计兜底，但信任边界仍在。
- **工作量**：≤1 窗口。

### 对比矩阵

| 维度 | A：candle/burn | B：libc shim + llama.cpp | C：远程代理 + 埋点 |
|------|---------------|--------------------------|-------------------|
| 工作量 | 3~6+ 窗口 | 6+ 窗口 | ≤1 窗口 |
| 失败风险 | 中（性能/算子覆盖） | 高（工具链碎裂、语义错配） | 低 |
| 生态（GGUF） | 部分（需自行转换裁剪） | 完整 | 无（不需要） |
| 架构一致性（cap/no_std/Doc 04） | ✅ | ❌ POSIX 暗道 | ✅ |
| 脱机能力 | 有（但受 C2/C3 排期阻塞） | 同 A | **无（明示承认）** |
| 技术栈同质 | ✅ | ❌ C++ | ✅ |
| 当前排期可行性 | ❌ 被 P6.0-T2/T3 + 存储栈双重阻塞 | ❌ 同左且更差 | ✅ 无新依赖 |

## 3. 推荐方案

**推荐 C + `InferenceProvider` trait 埋点**（即避坑指南 §5 的原生推荐路径）。

理由链：① 本地推理的两个硬前置（内存三件套、存储栈）本身未排期，A/B 在此时启动只会产出"能编译但装不进模型"的半成品；② 唯一刚需（脱机）尚未成为产品级阻塞——S1~S3 服务层（Doc 06 强制推进项）对推理的需求全部可由远程 API 满足；③ C 的埋点使未来切换到 A 是**增量**而非**返工**，决策可逆性好。

## 4. 再决策触发条件

满足**全部前置 + 任一触发**时重开本地推理决策（默认路径 A）：

- 前置：P6.0-T2（buddy）+ P6.0-T3（高端映射）+ 存储栈（模型落盘）完成；
- 触发①：脱机/断网成为真实部署场景的硬需求（如跨 OS 对抗演练、无网硬件交付）；
- 触发②：S4 记忆层 embedding 调用量大到远程 API 成本/延迟不可接受；
- 触发③：隐私合规要求推理不出机（本地小模型做敏感数据预过滤）。
